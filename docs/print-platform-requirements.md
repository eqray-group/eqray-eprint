## 0. 术语表

| 术语 | 含义 |
| --- | --- |
| 会员 | C 端下单用户，对应现有 `member_user`，与后台登录账号 `system_users` 分离 |
| 打印店 | 入驻平台的门店，拥有打印设备与定价能力 |
| 设备 | 安装在门店的客户端实例（一台 Windows PC 或一台 Android 设备） |
| 打印机 | 门店资产（物理打印设备），经绑定表供一台或多台设备使用 |
| 打印任务 | 一次「某个文件 + 一套打印参数 + 指定打印机」的执行单元，是客户端的工作单位 |
| 订单 | 用户一次下单行为，一个订单可拆成多个打印任务（多文件 / 多打印机） |
| 履约方式 | 快递发货、到店打印（到店自取成品） |

## 1. 目标与范围

### 1.1 目标

1. 用户用手机上传文件、选参数、看价格、下单支付，**不用装任何驱动**。
2. 门店用一台常驻客户端**自动接收任务并直接打印**，不需要人工下载文件、手动开打印对话框。
3. 两种履约方式共用同一套「文件 → 任务 → 打印」链路，只在**交付环节**分叉。

### 1.2 系统组成

```
用户端 uni-app ──┐
                 ├──► 后端服务（订单/计价/文件/任务调度）──► 打印店客户端 Flutter
门店后台 Web ────┤                                            （Windows / Android）
                 │                                                  │
平台运营后台 ────┘                                            物理打印机
```

四个入口共用一个后端：用户端（会员令牌）、门店后台（后台令牌 + 门店绑定）、
平台运营后台（后台令牌 + 平台角色）、打印店客户端（设备令牌）。

### 1.3 系统边界（明确不做）

| 不做 | 说明 |
| --- | --- |
| 自研支付通道 | 对接微信支付为主，预留支付宝；平台只做订单与退款状态机 |
| 自研物流轨迹 | 运单由门店录入，轨迹对接快递 100 / 快递鸟等第三方 |
| 在线排版编辑器 | 只提供纸张、色彩、单双面、份数、装订等**打印参数**，不做版面编辑 |
| 全品牌打印机驱动适配 | Windows 走系统打印子系统（spooler），Android 只支持 IPP / 厂商 SDK 静默打印 |
| 客户端代收银 | 客户端不涉及金额计算与收款，只展示服务端下发的价格 |
| 发票自动开具 | 走第三方开票平台，本系统只存开票状态 |

## 2. 角色与权限

### 2.1 角色定义

| 角色 | 载体 | 身份来源 | 数据范围 |
| --- | --- | --- | --- |
| 会员 | uni-app | 会员令牌（手机号验证码 / 微信登录） | 仅本人订单、文件、地址 |
| 店主 `SHOP_OWNER` | 门店后台 Web | `system_users` + RBAC | 本门店全部数据 |
| 店员 `SHOP_STAFF` | 门店后台 Web | `system_users` + RBAC | 本门店订单与任务（不可改价、不可审批退款） |
| 设备 `DEVICE` | Flutter 客户端 | 设备令牌（绑定门店 + 设备号） | 仅本设备的任务拉取与状态上报 |
| 平台运营 `PLATFORM_OPERATOR` | 平台后台 Web | `system_users` + RBAC | 全部门店的经营统计（只读），可下钻单店，不可改价、不可退款 |
| 平台财务 `PLATFORM_FINANCE` | 平台后台 Web | `system_users` + RBAC | 全平台结算与退款审批，不碰门店配置 |
| 平台管理员 | 平台后台 | `SUPER_ADMIN` | 全平台，含门店审核、异常任务干预 |

### 2.2 权限点（沿用 `模块:资源:动作` 规范）

| 角色 | 权限点 |
| --- | --- |
| 店主 | `print:shop:update`、`print:printer:*`、`print:device:*`（含 `print:device:bind`）、`print:price:*`、`print:order:list/accept/reject/ship/complete`、`print:task:list/retry/cancel`、`print:staff:*`、`print:settlement:view`、`print:stats:view`（限本店） |
| 店员 | `print:order:list/accept/ship/complete`、`print:task:list/retry`、`print:pickup:verify`（无统计权限，看不到金额类指标） |
| 平台运营 | `print:stats:view`、`print:stats:export`、`print:shop:read`（只读门店资料） |
| 平台财务 | `print:settlement:*`、`print:refund:audit`、`print:stats:view` |
| 平台管理员 | `print:shop:audit`、`print:order:*`、`print:task:intervene`、`print:config:*`、`print:stats:*`、`print:refund:audit` |
| 设备 | 无 RBAC，走专用设备令牌接口白名单 |

### 2.3 权限硬约束

- **C 端接口请求体与路径一律不出现 `memberId`**，会员身份只能从令牌取（与现有 `member` 模块约定一致）。
- **订单、任务、文件一律按归属校验**：跨门店、跨会员访问直接拒绝，不靠前端隐藏。
- 设备令牌**不得**访问订单金额、退款、门店配置类接口。
- 退款、改价仅店主或平台可操作，店员无此权限。
- **统计接口一律由服务端按 `shopId` 强制过滤**：店主只能看本店，平台运营可下钻任意门店，前端传参不能越权。
- 统计与导出**不得**包含用户隐私字段（手机号、收货地址、文件内容），需要订单明细时走脱敏 + 审批。
- 门店侧账号的 `shopId` **只能取自绑定关系**，接口传入的 `shopId` 一律忽略或直接拒绝。

### 2.4 后台账号与门店的绑定

**平台侧账号不绑店，门店侧账号必须绑店**，两者用不同的判断方式：

| 账号类型 | 是否绑定门店 | 数据范围来源 |
| --- | --- | --- |
| 平台管理员 / 平台运营 / 平台财务 | 否 | 角色即全局，`shopId` 只作为筛选条件 |
| 店主 `SHOP_OWNER` / 店员 `SHOP_STAFF` | 是 | `print_shop_staff` 绑定表，`shopId` 只能取自绑定关系 |

为什么不在 `system_users` 上直接加一个 `shop_id` 字段：

1. 连锁老板一个账号管多家店，单字段表达不了。
2. 换店、增加门店改的是授权关系，不该动账号表。
3. 同一个员工可能在 A 店是店长、B 店是店员，角色必须按店区分。
4. 账号与门店是多对多，用单字段会把「解绑」逼成「删账号」。

绑定模型：

```
system_users ──N:1── print_shop_staff ──N:1── print_shop
                        └─ role: owner / staff
```

| 表 | 关键字段 |
| --- | --- |
| `print_shop_staff` | `user_id`、`shop_id`、`role`(owner/staff)、`status`、`created_by`，`uk_user_shop(user_id, shop_id)` 唯一 |

会话与切换：

- 登录返回该账号的 `shopList`；为空说明既不是平台角色也没有门店授权，直接拒绝登录。
- 只有一家店时自动选中，不弹选择框；多家店时进入前选店，之后从顶栏切换。
- `currentShopId` **不放在前端请求参数里**，登录/切换时写入服务端会话并随令牌下发声明，接口只读会话值。
- 每次切换都校验 `print_shop_staff` 中存在该 `(user_id, shop_id)` 且 `status = 启用`。
- 解绑或禁用后立即失效：清掉会话中的 `currentShopId` 并前移权限缓存版本。

边界情况：

| 场景 | 处理 |
| --- | --- |
| 老板有多家店 | 一个账号绑定多条记录，登录后选店 / 切换 |
| 员工在 A 店是店长、B 店是店员 | `role` 按 `(user_id, shop_id)` 存，切换后权限随之变化 |
| 门店转让 | 新增/停用 `print_shop_staff` 记录，不动 `system_users` |
| 门店关停 | 绑定置停用，该店从 `shopList` 消失，历史数据保留可查 |
| 平台人员临时支援门店 | 额外绑一条 `staff` 记录，不修改其平台角色 |

**设备是另一条独立体系**：设备不占用 `system_users`，走 `print_device` + 设备令牌（见 4.2），
不要把门店电脑当成「一个后台账号」来管。

## 4. 打印店客户端（Flutter，Windows + Android）功能模块

### 4.1 实体关系：门店 / 设备 / 打印机

```
print_shop 打印店
  ├── 1:N print_device      打印设备（客户端实例：一台 PC 或一台 Android 平板）
  │        └── N:N print_printer（通过 print_device_printer 绑定）
  ├── 1:N print_printer     打印机（门店资产，不随设备走）
  └── 1:N print_shop_staff  店员（映射 system_users）

print_order ──1:N── print_task ──N:1── print_printer
                              └──N:1── print_device
```

一句话：**设备是「谁来干活」，打印机是「用什么干」，打印店是这两者的归属边界**。

| 关系 | 基数 | 约束 |
| --- | --- | --- |
| 打印店 → 设备 | 1 : N | 设备必须且只能属于一个门店；解绑后需重新激活 |
| 打印店 → 打印机 | 1 : N | 打印机是门店资产，记录型号、能力、生命周期状态 |
| 设备 → 打印机 | N : N | 通过绑定表维护；本地打印机只绑一台设备，网络打印机可多设备共享 |
| 任务 → 打印机 | N : 1 | 任务创建时确定，执行中不可换机 |
| 任务 → 设备 | N : 1 | 与打印机同时确定，保证「哪台机器打的」可追溯 |

**为什么打印机挂门店而不是挂设备**：

1. 换电脑、重装系统不丢失能力配置（纸张、托盘、彩色、双面）。
2. 网络打印机（IPP）天然被多台设备共享，挂设备会产生重复记录。
3. 任务按「能力」路由：A4 彩色任务只要求门店内有满足能力的打印机，某台设备故障时可改派同店其他设备。
4. 后台需要按打印机统计产能、耗材、故障率，按设备统计没有业务意义。
5. 打印机的采购、维修、报废属于资产生命周期，归属门店更自然。

**任务路由顺序**（服务端）：

1. 取订单明细的 `(paper, color, duplex, binding)`。
2. 门店内筛 `printer.status = 启用` 且能力满足的打印机。
3. 再筛这些打印机绑定的、`device.status = 在线` 且未摘机的设备。
4. 按 `is_default` 优先、当前队列最短，选出唯一的 `(deviceId, printerId)`。
5. 订单要求「同店同设备装订」时，整单锁定同一 `deviceId`。

### 4.2 客户端登录与设备激活

客户端**不使用账号密码登录**，也不复用会员令牌或后台令牌，只走「设备激活 → 设备令牌」。

首次激活：

1. 店主在后台「打印店 → 设备管理」生成**绑定码**（一次性、10 分钟有效、绑定 `shopId`，可展示为二维码）。
2. 客户端首次启动进入激活页，输入「门店编号 + 绑定码」或直接扫码。
3. 调 `POST /api/v1/client/print/device/activate`：

```
请求：{ shopCode, bindCode, deviceName, platform(windows|android),
        osVersion, clientVersion, machineFingerprint }
响应：{ deviceId, shopId, shopName,
        accessToken, refreshToken, expiresIn,
        wsUrl, minClientVersion }
```

4. 令牌写入系统安全存储：Windows DPAPI、Android Keystore；**禁止**明文配置文件与日志。
5. 激活成功即上报本机打印机清单（`POST /device/printers/sync`），服务端据此维护
   `print_printer` 与 `print_device_printer` 绑定关系。

后续启动：

```
读本地令牌 → GET /device/profile（校验门店状态与令牌有效性）
  → 建立 WS 连接 → 心跳 30s → 拉取未终态任务
令牌过期 → POST /device/refresh 换新 → 失败则回激活页
```

令牌设计：

| 项 | 规则 |
| --- | --- |
| 作用域 | 新增 `ScopeDevice`，与 `ScopeAdmin` / `ScopeMember` 隔离，Redis 键 `auth:device:access:<hash>` |
| accessToken | 2 小时，用于接口调用与 WS 握手 |
| refreshToken | 90 天，滑动续期，每次刷新轮换 |
| 吊销 | 后台「解绑设备」删除 Redis 键并置 `device.status = 已解绑`，客户端下次请求即回激活页 |
| 绑定信息 | 令牌内含 `deviceId + shopId`，服务端所有查询强制带 `shopId` 条件 |

设备令牌只能访问以下白名单，**不得**触达订单、金额、退款、门店配置：

| 方法 | 路径 | 说明 |
| --- | --- | --- |

## 5. 业务流程

### 5.1 公共主流程（两种履约方式共用）

```
选门店 → 上传文件（服务端转 PDF、算页数）→ 配置参数（服务端计价）
   → 选履约方式 → 提交订单（服务端二次计价并锁价）
   → 支付 → 门店接单（手动或超时自动）→ 拆解打印任务下发
   → 客户端打印 → 任务成功 → 订单进入交付环节 →（快递 / 到店）→ 完成
```

### 5.2 快递发货流程

1. 用户选择收货地址，服务端按运费模板计算运费。
2. 支付成功即**自动接单并立即下发打印任务**（门店开启「人工确认」时需店员点接单，默认关闭）。
3. 客户端自动打印并装订；全部任务成功后订单进入「待发货」，客户端弹出运单录入框。
4. 门店录入快递公司 + 运单号 → 订单「已发货」→ 通知用户。
5. 用户签收或发货后 T+7 自动确认收货 → 订单「已完成」。
6. 已发货后**不再支持主动退款**，只走售后（免费重打 / 部分补偿）；确需退款由平台财务审批。
7. 售后窗口：确认收货后 7 天内可申请质量售后。

### 5.3 到店打印流程

1. 用户选门店取件（不填地址、不收运费），提交订单即生成**取货码（6 位数字）+ 二维码**。
2. 支付成功即**自动接单并立即下发打印任务**，设备开始打印，**不等用户到店核销**。
3. 打印完成（全部任务成功）后订单进入「待取件」（`PICKUP_READY`），向用户推送「已可取货」通知，
   取货码在订单详情与消息中展示，同时下发到客户端供店员核对。
4. 用户到店出示取货码 / 二维码，店员核销 → 订单「已完成」。
5. 保留期 7 天，期间未取件提醒两次；到期未取 → 关闭并标记「超期未取」，**默认不退款**（成品已产出）；
   店主可发起退款申请，由平台财务审批，该规则须在订单详情页明示。
6. 打印失败（重试耗尽）→ 订单转「退款中」并全额退款，此时取货码立即作废，通知用户重新下单。

### 5.4 关键差异对比

| 维度 | 快递发货 | 到店打印 |
| --- | --- | --- |
| 收货信息 | 必填地址 | 不需要地址，需选门店 |
| 运费 | 按模板计费 | 无 |
| 打印时机 | 支付成功即自动打印 | 支付成功即自动打印（同样不等核销） |
| 交付动作 | 录运单 → 已发货 → 签收 | 取货码核销 → 已完成 |
| 超时策略 | 人工确认模式下 30 分钟未接单转派/退款 | 7 天未取件关闭（默认不退款） |
| 售后入口 | 确认收货后 7 天 | 完成当日 |

## 6. 状态流转

### 6.1 订单状态

| 值 | 状态 | 含义 | 可流转到 |
| --- | --- | --- | --- |
| 10 | `PENDING_PAY` | 待支付 | 20 支付成功；80 用户取消；82 超时关单 |
| 20 | `PAID` | 已支付（默认自动转 30，人工确认模式下暂留） | 30 自动/人工接单；90 拒单或超时退款 |
| 30 | `ACCEPTED` | 已接单 / 待打印（支付后自动进入） | 40 首个任务开始；90 退款 |
| 40 | `PRINTING` | 打印中 | 50 快递：制作完成；65 到店：待取件；90 打印失败转退款 |
| 50 | `PRODUCED` | 制作完成（快递专用，待发货） | 60 已发货；90 退款 |
| 60 | `SHIPPED` | 已发货 | 70 签收 / 自动确认 |
| 65 | `PICKUP_READY` | 待取件（到店专用） | 70 核销完成；82 超期关闭 |
| 70 | `COMPLETED` | 已完成 | —（仅售后流程） |
| 80 | `CANCELLED` | 已取消 | — |
| 82 | `CLOSED` | 已关闭（超时/超期） | — |
| 90 | `REFUNDING` | 退款中 | 91 退款成功 |
| 91 | `REFUNDED` | 已退款 | — |

约束：

- **50 与 65 互斥**：快递订单只走 50，到店订单只走 65，禁止用同一状态表达两种履约语义。
- 状态只能**单向推进**，禁止回退；需要补救时走退款 + 重新下单。
- 所有状态变更必须写状态流水（操作人、来源、时间、备注），客户端不可直接改状态，只能上报任务结果，由服务端聚合推导订单状态。
- 订单状态由任务状态**聚合驱动**：任一任务失败且重试超限 → 订单转「退款中」并告警；全部任务成功 → 按履约方式转「制作完成」或「待取件」。
- 进入 `SHIPPED` 或 `PICKUP_READY` 后不再支持主动退款，只能走售后或平台财务审批。

### 6.2 打印任务状态

| 值 | 状态 | 含义 | 触发方 |
| --- | --- | --- | --- |
| 10 | `CREATED` | 已创建，待下发 | 服务端（订单支付/核销后拆解） |
| 20 | `DISPATCHED` | 已推送，待客户端领取 | 服务端 |
| 30 | `CLAIMED` | 客户端已领取 | 客户端 |
| 35 | `DOWNLOADING` | 下载文件中 | 客户端 |
| 40 | `PRINTING` | 打印中 | 客户端 |
| 50 | `SUCCESS` | 打印成功 | 客户端回执 |
| 60 | `FAILED` | 打印失败 | 客户端回执，可重试 |
| 70 | `CANCELLED` | 已取消（订单取消/退款） | 服务端 |
| 80 | `EXPIRED` | 已过期（长时间无设备领取） | 服务端定时任务 |

### 6.3 任务流转图

```
CREATED ──推送──► DISPATCHED ──领取──► CLAIMED ──► DOWNLOADING ──► PRINTING
                     │                                              │
                     │ 3 次无 ACK                                    ├──► SUCCESS
                     ▼                                              └──► FAILED ──重试(≤3)──► DISPATCHED
                  EXPIRED                                                 │
                                                                    超限 → 转人工 + 订单退款
任意非终态 ──订单取消/退款──► CANCELLED
```

## 7. 客户端任务接收与打印交互

### 7.1 连接与心跳

| 项 | 规则 |
| --- | --- |
| 主通道 | WebSocket（`wss`）常驻，携带设备令牌，握手时上报设备版本与打印机列表 |
| 兜底通道 | HTTP 轮询，间隔 30s；WS 断连超过 60s 自动切换 |
| 心跳 | 客户端 30s 一次；服务端 90s 未收到判离线，离线设备不再接收新任务并告警 |
| 重连 | 指数退避 1s→2s→5s→10s→30s 封顶，重连成功后全量拉取未终态任务 |
| 时钟 | 客户端以服务端时间为准，偏差 > 2 分钟时拒绝接单并提示校对系统时间 |

### 7.2 任务推送与确认

1. 服务端按「门店 + 打印机能力」路由任务，推送体包含：

```
taskId, taskNo, orderNo, deviceId, fileUrl(签名,10 分钟), fileSha256, fileSize,
fileName, pages, pageRange, copies, paper, color, duplex, binding,
printerId, deadline(绝对时间戳), pickupCode(到店)
```

2. 推送体是打印参数**唯一权威来源**：客户端不二次加工、不读本地默认值、门店后台也不能临时改参数；
   能力不匹配只能回执失败，禁止降级执行。
3. 客户端收到后**必须先本地落库再 ACK**（SQLite），ACK 后服务端转 `CLAIMED`。
4. 10s 内未收到 ACK，服务端按 10s / 30s / 60s 重推，3 次后任务转 `EXPIRED` 并告警。
5. 重推不产生重复打印：客户端按 `taskId + taskNo` 去重，已存在且已打印则只补回执。

### 7.3 下载与校验

- 使用签名短链下载，链接过期则调用「刷新下载地址」接口重新获取（不重新计价、不重新拆任务）。
- 校验：HTTP 200 + 文件大小一致 + SHA-256 一致，任一不符按 `FILE_BROKEN` 失败重试。
- 下载完成后文件存放于应用私有目录，任务成功后按保留策略删除（默认立即删除，可配保留 24h 便于补打）。

### 7.4 打印执行

| 平台 | 执行方式 | 交互 |
| --- | --- | --- |
| Windows | 调用系统打印子系统静默打印 PDF（指定打印机、纸张、份数、单双面、托盘） | 全程无系统弹窗，界面只显示进度 |
| Android | IPP 网络打印机直连或厂商 SDK 静默打印，不走系统 Print Framework 的人工确认流程 | 全程静默，无任何交互对话框；打印机不具备静默能力时拒绝接单 |

打印参数落地规则（必须遵守，否则版式错乱）：

- **参数只读**：纸张、色彩、单双面、份数、页范围、装订全部取自服务端推送体，客户端与门店后台均不得本地覆盖。
- **100% 不缩放**、按 PDF 页面尺寸自动匹配纸张，禁止「适应页面」拉伸。
- 单双面由服务端参数决定，客户端不得自行翻转。
- 彩色任务遇到仅黑白打印机时**必须失败**并回执 `COLOR_UNSUPPORTED`，不得降级打印。
- 份数 > 1 时按份连续输出，不得逐页重复（避免装订错乱）。
- 装订为人工动作，客户端只负责打印后在界面上提示「需订书 / 需胶装」。

### 7.5 回执与异常

| 错误码 | 场景 | 客户端处理 | 服务端处理 |
| --- | --- | --- | --- |
| `PAPER_JAM` | 卡纸 | 提示店员处理后重试 | 记录，计入设备健康度 |
| `NO_PAPER` | 缺纸 | 提示补纸后重试 | 同上 |
| `PRINTER_OFFLINE` | 打印机离线 | 摘机，切备用打印机或等待 | 任务保留，不自动取消 |
| `FILE_BROKEN` | 下载校验失败 | 刷新链接重下，≤3 次 | 超限转人工 |
| `COLOR_UNSUPPORTED` | 参数与设备不匹配 | 不打印 | 自动改派其他设备 |
| `TIMEOUT` | 单任务超 10 分钟未完成 | 中断并可重试 | 告警 |

统一规则：

- 回执必须带 `printedPages`（实际输出页数）与 `costMs`，服务端据此核对是否缺页。
- 失败**重试上限 3 次**（即最多尝试 4 次），重试耗尽后任务置 `FAILED` 并**摘除设备自动接单**，需人工恢复。
- 同一台打印机**串行执行**，前一个任务未终态不取下一个；不同打印机可并行。
- 单设备同一时刻最多 1 个打印中任务，其余排队（队列上限 50，超出停止接单）。

### 7.6 离线与断电

- 断网时已领取的任务**允许继续打印**，回执进入本地重试队列，恢复后按时间顺序补传。
- 断电/崩溃重启后：`PRINTING` 状态任务标记为「结果未知」，客户端重启后向服务端查询该任务最终状态，避免重复打印。
- 本地队列与回执至少保留 7 天，供对账。

## 8. 订单与任务的数据拆分规则

| 规则 | 说明 |
| --- | --- |
| 一单多文件 | 每个文件生成一条订单明细，明细携带各自的参数 |
| 一明细多任务 | 同一文件因能力或交付要求需拆机时（如彩色页走彩机、装订件单独出），拆成多条任务 |
| 任务与设备/打印机绑定 | 任务创建时同时确定 `deviceId` 与 `printerId`，执行中不可换机（换机需服务端重建任务） |
| 计价粒度 | 按「明细」计价，订单金额 = 明细合计 + 运费 + 加急费 − 优惠 |
| 页数依据 | 以服务端转 PDF 后的实际页数为准，客户端展示的页数不得作为计价依据 |
| 任务顺序 | 同订单任务按明细顺序下发，装订类订单要求同店同设备完成 |

## 9. 核心约束

| 编号 | 约束 |
| --- | --- |
| C1 | 输入格式仅 PDF / JPG / PNG / DOCX；DOCX 由服务端统一转 PDF，**客户端只接收 PDF** |
| C2 | 单文件 ≤100MB，单订单 ≤20 个文件；单份 ≤500 页且「页数 × 份数」≤5000 印张 |
| C3 | 页数与金额只在服务端计算，客户端与前端展示均以服务端返回为准，禁止本地重算 |
| C4 | 文件访问使用带时效的签名地址，禁止公开可猜测 URL；有效期内可续签，不可永久有效 |
| C5 | 打印防重：`taskNo` 全局唯一，客户端本地记录已打印任务，重复推送只补回执 |
| C6 | 订单不可跨门店；任务的设备与打印机在创建时锁定，改派只能由服务端重建任务 |
| C7 | 未打印可全额退款；已打印默认不退，质量异常走售后免费重打或平台财务审批退款 |
| C8 | 到店订单保留期 7 天，到期未取按 5.3 处置；快递订单发货后 T+7 自动确认收货 |
| C9 | 待支付订单 30 分钟自动关闭；开启「人工确认」的门店，支付后 30 分钟仍无人接单则转派或自动退款 |
| C10 | 设备令牌与会员令牌、后台令牌**三者作用域隔离**，不可互用 |
| C11 | 客户端版本低于服务端最低版本时禁止接单，必须先升级 |
| C12 | 客户端不得持久化文件内容超过配置的保留时长，成功后默认立即删除 |
| C13 | 日志与埋点不得记录文件内容、完整手机号、完整地址，手机号一律掩码 |
| C14 | 服务端时间为唯一时间基准；客户端时间偏差过大时拒绝接单 |
| C15 | 同一打印机串行执行；同一设备同一时刻只允许 1 个打印中任务 |
| C16 | 打印参数以服务端任务体为唯一来源，客户端与门店后台均不得覆盖；能力不匹配只能失败，不得降级打印 |
| C17 | Android 端必须静默打印，仅接入 IPP / 厂商 SDK 打印机；无静默能力时拒绝接单并上报 |

## 11. 平台运营与门店统计

运营可以在平台后台看到**每家门店的经营统计**，并按门店下钻；店长在自己后台看到的是同一套指标的「本店版」。
两边复用同一份统计实现，差异只在数据范围。

### 11.1 数据范围

| 角色 | 可见范围 | 说明 |
| --- | --- | --- |
| 平台运营 | 全平台汇总 + 任意单店下钻 | 只读，不可改价/退款；导出需权限点 |
| 平台财务 | 全平台结算、退款与分成 | 可审批退款，不可改门店配置 |
| 平台管理员 | 同上 + 门店审核与异常干预 | — |
| 店主 | 仅本店 | `shopId` 由账号绑定关系决定，接口不接受外部传入的 `shopId` |
| 店员 | 无统计权限 | 只看打印店客户端的今日看板（4.7 C-OPS-01），不含金额 |

### 11.2 门店统计指标

按「门店 × 日期」预聚合，支持汇总视图与单店视图：

| 分类 | 指标 |
| --- | --- |
| 交易 | 支付订单数、GMV、退款额、净收入、客单价、加急费、运费收入 |
| 履约 | 快递单占比、到店单占比、接单平均耗时、超时未接单数、到店核销率、7 天未取件数 |
| 生产 | 任务数、成功数、失败数、成功率、重试次数、平均打印耗时、黑白页数、彩色页数、装订单数 |
| 设备 | 在线设备数、设备在线率、打印机故障次数、错误码分布（卡纸 / 缺纸 / 离线 / 文件损坏） |
| 用户 | 下单会员数、新客数、复购率 |
| 质量 | 售后单数、售后率、平均评分（若启用评价） |

### 11.3 筛选与粒度

- 时间：今日、昨日、近 7 天、近 30 天、自定义区间（单次最长 90 天）。
- 粒度：按日 / 按周 / 按月；单店详情提供趋势图与环比、同比。
- 筛选：门店（多选）、履约方式、纸张、色彩、订单状态。
- 排序：GMV、订单量、成功率、平均耗时，支持升降序。

### 11.4 统计口径（必须写在页面提示里，避免店长与运营对不上数）

| 指标 | 口径 |
| --- | --- |
| GMV | 按**支付成功时间**归集，含后续已退款订单的原始金额；净收入 = GMV − 退款额 |
| 订单数 | 只统计已支付订单（`PAID` 及之后），不含待支付与已取消 |
| 退款额 | 按**退款成功时间**归集，与 GMV 口径不同周期，两者不可直接相减 |
| 页数 | 以任务回执 `printedPages` 为准；重打单独计入「重打页数」，不重复计入产出 |
| 成功率 | 成功任务数 ÷（成功 + 失败），不含取消与过期任务 |
| 平均耗时 | 从 `CLAIMED` 到 `SUCCESS` 的时长，剔除超过 10 分钟的异常样本 |
| 到店核销率 | 已核销订单数 ÷ 到店订单数（仅统计已制作完成） |
| 时区 | 统一东八区，日切点 00:00 |

### 11.5 实时性

- **T+1 离线聚合**：每日 01:00 跑批，把前一天数据写入 `print_shop_stats_daily`，历史查询全部走预聚合表。
- **当日实时**：今日数据用 Redis 计数器 + 5 分钟小聚合，页面标注「今日为实时数据，昨日及以前为结算数据」。
- 跑批失败必须告警并提供补跑入口，不允许静默缺失。

### 11.6 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/print/stats/overview` | 全平台总览（运营） |
| GET | `/api/v1/print/stats/shops` | 门店统计列表（分页 + 排序 + 筛选） |
| GET | `/api/v1/print/stats/shops/{id}` | 单店详情：指标卡 + 趋势 + 错误码分布 |
| GET | `/api/v1/print/stats/shop/me` | 店主页，服务端强制本店 |
| POST | `/api/v1/print/stats/shops/export` | 异步导出 Excel，生成文件后走 `infra_file` 下载 |

约束：

- 列表接口单次最多返回 100 行；导出上限 10 万行且异步生成，禁止同步全量查询。
- 统计与导出全部写 `OperateLog` 留痕（谁在何时导出了哪些门店的数据）。
- 门店列表需能一眼识别「零单门店」与「高失败率门店」，这是运营最常用的两个排查入口。

## 12. 验收要点

### 12.1 用户端

- [ ] 上传 3 个文件（PDF + JPG + DOCX）可正常解析页数并计价。
- [ ] 改参数后金额实时变化，与后台价格表一致。
- [ ] 快递订单可选用已有地址并正确计算运费；到店订单无运费且生成取货码。
- [ ] 未支付取消、已支付未打印全额退款、已打印默认不退三条规则均生效。
- [ ] 已打印出现缺页 / 错版时走售后免费重打，不产生新的收费订单。
- [ ] 支付成功后客户端立即开始打印，全程无需人工点确认；取货码在打印完成前即可查看。

### 12.2 客户端

- [ ] 断网 5 分钟后恢复，未终态任务自动补齐，无重复打印。
- [ ] 关闭客户端 10 分钟后重启，`PRINTING` 任务不重复输出。
- [ ] 拔掉打印机电源，任务失败并回执 `PRINTER_OFFLINE`，设备摘机。
- [ ] 彩色任务在黑白打印机上失败并回执 `COLOR_UNSUPPORTED`，不降级打印。
- [ ] Windows 与 Android 均全程静默，无系统打印对话框；Android 用 IPP 网络打印机验证。
- [ ] 门店后台改了默认纸张后，已下发任务仍按服务端参数打印，不被本地配置覆盖。
- [ ] 一台设备绑定 2 台打印机，可并行打印不同任务且互不串页。
- [ ] 设备被后台解绑后，10 秒内停止接单并回到激活页；重新激活后可正常接单。

### 12.3 订单与任务

- [ ] 两种履约方式的状态流转无跳变，流水完整。
- [ ] 任务全成功 → 订单自动「制作完成」；任务失败超限 → 订单「退款中」并告警。
- [ ] 到店 7 天未取件按未打印/已打印分别处置。
- [ ] 跨门店、跨会员越权访问订单返回 403。

### 12.4 运营统计

- [ ] 运营账号可看到全部门店列表与汇总，能下钻任意单店趋势。
- [ ] 店主账号调用同一接口只能拿到本店数据，篡改 `shopId` 仍返回本店。
- [ ] 店员账号无统计权限，接口返回 403。
- [ ] 昨日及以前数据来自预聚合表，今日数据为实时值，页面有口径提示。
- [ ] 导出仅在权限点允许时可用，且生成导出记录（谁、何时、哪些门店）。
- [ ] 一个账号绑定两家店时，切换门店后只能看到当前店数据；解绑后立即失去该店访问权。
